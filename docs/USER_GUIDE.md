# Donkey user guide

Donkey is a native binary reverse-engineering workbench: a desktop program
(`donkey`) and a command-line program (`donkey-cli`) built on the same core.
It reads ELF, PE and Mach-O files (and raw blobs), disassembles x86, x86-64
and AArch64, recovers functions, control flow, call graphs and jump tables,
decompiles a verified subset to C-like pseudocode, keeps your work in project
databases, patches copies of files, and debugs programs on Linux and Windows.

Opening a file only reads it. Donkey never runs a program unless you start
it under the debugger and confirm. It has no telemetry, no updater and makes
no network connections.

## Installing

| Platform | Package | Install |
|---|---|---|
| Linux x86_64 / arm64 | `.deb`, `.rpm`, `.tar.gz` | `sudo apt install ./donkey_*.deb`, `sudo dnf install ./donkey-*.rpm`, or unpack the archive anywhere and run `bin/donkey` |
| macOS arm64 (11+) | `.dmg`, `.zip` | Drag Donkey.app to Applications. `donkey-cli` is in `Donkey.app/Contents/MacOS`. The app is ad-hoc signed, not notarised: the first time, right-click → Open. |
| Windows x86_64 / arm64 | setup `.exe`, `.zip` | Run the installer (it can add `donkey-cli` to PATH), or unzip the portable build |
| FreeBSD amd64 / aarch64 | `.pkg`, `.tar.gz` | `pkg add donkey-*.pkg` |

Each release asset has a `.sha256` file. Every package contains
`LICENSE`, `THIRD_PARTY_NOTICES`, this guide and `donkey.spdx.json` (an SPDX
2.3 bill of materials).

## The workspace

Open a file with **File → Open File…**, by dropping it on the window, or on
the command line: `donkey /path/to/program`. Panels dock and can be dragged
anywhere. **View → Reset Layout** restores the default arrangement. The
layout is saved per user (`~/.local/share/Donkey/Donkey` on Linux, the
equivalent preference folder elsewhere).

| Panel | Shows |
|---|---|
| Overview | Format, architecture, entry point, SHA-256, analysis status, DWARF summary |
| Sections | Sections with addresses, sizes and permissions |
| Functions | Discovered functions with size and block count. A tooltip shows the DWARF prototype; below it are the selected function's callers and callees. |
| Disassembly | Every decoded instruction, filterable. Double-click a target to follow it. Right-click to rename, comment, bookmark or edit function boundaries. |
| Graph | The selected function's control-flow graph: pan, zoom, search |
| Decompiler | Pseudocode for the selected function, labelled Complete, Partial or Unsupported |
| Hex | Bytes at the selection; click a byte to stage a patch |
| Strings, Xrefs, Bookmarks | Navigation lists |
| Debugger | Native debugging (see below) |
| Diagnostics | Everything the loader or analysis could not do, by code |

Status words are always written out, not only coloured. **Partial** means
some of the result could not be established. Donkey shows what it knows and
says what is missing, rather than guessing.

### Keyboard

| Key | Action |
|---|---|
| G | Go to an address (hex) or a function or symbol name |
| N | Rename the selected address |
| ; | Comment the selected address |
| Ctrl/Cmd+B | Toggle a bookmark |
| Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z | Undo, redo annotation edits |
| Alt+Left, Alt+Right | Back, forward through navigation history |
| Tab, arrows, Enter, Space | Move between and use controls (keyboard navigation is on) |
| Ctrl+Tab | Switch panels |
| Esc | Cancel a dialog, or a running load or analysis |

## Projects

**File → Save Project** writes renames, comments, bookmarks and
function-boundary edits to a SQLite database. Opening it later reloads the
binary and your edits. **Backup Project** writes a consistent copy;
**Restore Project** checks a backup (schema, tables, integrity) before
replacing the open project atomically. Projects from older Donkey versions
are migrated when opened. Projects from newer versions, or damaged ones, are
refused without changes.

Names from debug information never replace your renames. Your edit is shown,
and the imported name stays available with its source (for example
`DWARF 5 @0x244`).

## Decompiler

Pseudocode is printed only from intermediate code that passed a verifier.
It is never assembled from text and never generated by a model.

- **Supported:** integer code for x86-64, x86-32 (subset) and AArch64,
  including branches, loops, switches through recovered jump tables, stack
  locals, structs behind pointer arguments, and conditional moves.
- **Partial:** floating point, SIMD (vectorised loops at -O3), calls'
  effects, and flags that cannot be modelled exactly. The note lines in the
  pseudocode say which applies.
- **How it is tested:** `docs/SUPPORT_MATRIX.md` lists the measured results.

## Patching

In the Hex panel, click a byte and type the new value. Patches are staged
and shown in orange; **Export** writes a patched copy and never modifies the
original. The original bytes are checked before writing, and a failed export
leaves no partial file. `donkey-cli patch apply` does the same from scripts.

## Debugging

Native debugging works on Linux (x86-64, AArch64) and Windows (x64).
macOS, FreeBSD and Windows on Arm cannot debug yet, and the Debugger panel
says so.

**Launch…** asks for confirmation, because debugging runs the program with
your permissions. Breakpoints are set on static addresses and follow ASLR
and libraries loaded later. Registers, stack, threads, modules and memory are
shown only while the program is stopped, never stale.

- **Linux:** attaching to a process you did not start needs `CAP_SYS_PTRACE`
  or `/proc/sys/kernel/yama/ptrace_scope` set to 0. Donkey reports exactly
  this when an attach is refused.
- **Windows:** protected and higher-integrity processes cannot be attached.

## donkey-cli

Every command accepts `--json` for scripts (versioned, deterministic output)
and works without a display.

```bash
donkey-cli info program --json
donkey-cli functions program
donkey-cli decompile program --function 0x401000
donkey-cli callgraph program --json
donkey-cli debuginfo program            # DWARF functions, types, variables
donkey-cli project save project.donkey program
donkey-cli patch apply program --offset 0x1234 --replacement 90 --output patched
donkey-cli debug launch program --break 0x401000 --run
```

`donkey-cli --help` lists every command and option.

## Troubleshooting

- **The window is black or the app exits at start:** run
  `donkey --renderer software`. Donkey falls back from SDL_GPU (Vulkan,
  Direct3D 12, Metal) to SDL_Renderer automatically. The flag forces the
  software path.
- **A panel is gone:** use the View menu, or **View → Reset Layout**.
- **Analysis is slow on a huge file:** files of 64 MiB or more are memory
  mapped. Progress shows in the status bar, and Esc cancels.
- **Reporting a problem:** include `donkey --version`, the platform, and the
  Diagnostics panel's codes. Donkey collects nothing by itself.
