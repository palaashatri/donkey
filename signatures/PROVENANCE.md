# Shipped signature sets

Each set here is generated by `donkey-cli sig make` from a library that Donkey's licence review
allows to redistribute derived data (`docs/IDA_GAP_LEDGER.md`, G09-T3). The set is data derived from
the library's symbols and machine code; it does not contain the library.

## musl-1.2.4.json

- **Library:** musl libc 1.2.4, `libc.a`, from the Ubuntu 24.04 `musl-dev` package, version 1.2.4-2.
  Licence: MIT (`/usr/share/doc/musl/copyright` in the `musl` package, `License: MIT`).
- **Input:** `/usr/lib/x86_64-linux-musl/libc.a`, SHA-256
  `657e951f4c1d02ecac4e424222034c84a189f361b090f1284f255b3ac4480d5c`.
- **Command:** `donkey-cli sig make /usr/lib/x86_64-linux-musl/libc.a --lib musl --version 1.2.4
  --license MIT --out signatures/musl-1.2.4.json`
- **Output:** `musl-1.2.4.json`, SHA-256
  `d19dcf651500970275e4a5a9fdba457994736de4f66753ee0afc5562a9b16210`. 2,096 signatures, 1,653 with
  wildcards, 0 skipped, not partial. Architecture x86_64.
- **Compiler of the library:** the Ubuntu package's own build (GCC 13.3.0 for x86-64); this set was not
  built here.
- **Used by:** `Signatures.IdentifyMuslFunctionsInAStaticBinary` (`tests/unit/signatures_musl_test.cpp`),
  against `tests/fixtures/sig/musl/sig_musl`.

To regenerate: install `musl-dev` 1.2.4-2 (or the same build), run the command above, and compare the
hash. A different build of musl gives different bytes, so the hash changes with the package.
